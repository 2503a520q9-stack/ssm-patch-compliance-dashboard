⚠️ Problem Statement & Challenges
Context

🚨 Enterprise Patching Risks

  • Unpatched operating systems are the #1 attack vector for security breaches and CVE exploits.
  • Auditing hundreds of servers across multiple cloud environments manually is slow and error-prone.
  • Operations teams lack immediate, glanceable health status during critical security windows.

⚙️ The Operational Gap

  • Console Fatigue: Navigating deep AWS menus just to check compliance slows down response times.
  • Pending Reboot Visibility: Servers frequently install security patches but remain vulnerable until rebooted.
  • Need for NOC Simplicity: Operations centers require an instant 3-state traffic light visual board.
Speaker Notes: Explain why patch monitoring matters: security breaches stem from missing updates. Highlight that deep cloud menus create operational lag, motivating a simple 3-LED traffic light display.
💡 The Solution: 3-LED Light Board
Concept

A centralized, real-time visual light board inspired by industrial status panels, backed by AWS Systems Manager and serverless cloud automation.

🟢 COMPLIANT

All instances satisfy approved baseline patch policies. Zero missing security updates and zero pending reboots.

🟡 PENDING

Updates have been staged or installed that require an immediate system reboot, or an instance scan is currently pending.

🔴 NON-COMPLIANT

One or more instances are actively missing critical security updates or failed the automated baseline scan.

Speaker Notes: Present the 3 LED states. Emphasize that Yellow is critical because a patched server without a reboot is still running old vulnerable memory code.

🔒 Zero Inbound Ports

The SSM Agent communicates over outbound HTTPS (port 443). No open inbound SSH (port 22) or web ports required on servers.

⚡ Serverless Decoupling

The dashboard never holds AWS credentials. It consumes a lightweight JSON payload generated on-demand by AWS Lambda.

🛠️ AWS Systems Manager & Patch Manager
Cloud Infrastructure

📋 Patch Baselines

  • Evaluates fleet against AWS-DefaultPatchBaseline.
  • Automatically classifies updates by classification: Security, Bugfix, and Critical advisories.
  • Configured with custom approval rules and compliance severity levels.

🚀 Automated Execution

  • Executes via SSM Run Command document: AWS-RunPatchBaseline.
  • Supported operations: Scan Only (inspection) and Scan & Install (remediation).
  • Stores compliance diagnostic snapshots directly in SSM Compliance store.
Speaker Notes: Detail how SSM works. Explain that AWS-RunPatchBaseline audits installed RPM packages against upstream Amazon Linux security advisories.
🧠 Serverless Backend: AWS Lambda
Logic Tier

⚙️ The Lambda Evaluator

  • Function: PatchComplianceEvaluator (Python 3.12).
  • Assigned pre-configured LabRole (compatible with AWS Learner Lab IAM policies).
  • Calls Boto3 APIs: describe_instance_information and describe_instance_patch_states.

🌐 Lambda Function URL

  • Provides direct HTTPS invocation without complex API Gateway setup.
  • Built-in CORS headers allow local and browser-based client requests.
  • Bypasses 4-hour Learner Lab session credential expiration issues on local client.
Speaker Notes: Explain how Lambda solves the AWS Learner Lab session timeout problem: since Lambda runs inside AWS with LabRole, the local client never needs temporary access tokens.
💻 Frontend Dashboard & VS Code Workflow
Presentation Tier

🎨 Interactive Light Board (Streamlit)

  • Glowing radial gradient CSS with realistic neon illumination.
  • Real-time KPI metrics: Total Nodes, Compliant Nodes, Pending, and Non-Compliant.
  • Detailed diagnostic table showing instance IDs, operating system, and last scan timestamps.

🕹️ Simulation & Live Modes

  • Live Mode: Real-time REST call to AWS Lambda URL.
  • Interactive Demo Controls: 1-click toggles to simulate Yellow (Pending Reboot) and Red (Critical Vulnerability) for examiner presentations.
  • Packaged cleanly to run with python -m streamlit run app.py in VS Code.
